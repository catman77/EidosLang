# EidoLang

Мессенджер, в котором сообщения — не текст, а **эйдограммы**: фигуры, собранные в осмысленную
композицию. Значения не назначены заранее и не расшифровываются словарём — они рождаются в
переписке. Это следствие центрального запрета проекта: написать «красный = сила, треугольник =
действие» значило бы превратить эйдографию в пиктографию.

Техническая сторона подчинена той же идее — не зависеть от посредника:

* **Сквозное шифрование.** Ключ сообщения заворачивается отдельно под каждое устройство получателя;
  расшифровка происходит при чтении, открытых эйдограмм в базе не хранится.
* **Знакомство без сервера.** QR-код или ссылка, визитка забирается прямо с устройства собеседника
  через Tor.
* **Доставка без сервера.** Каждое устройство отдаёт свои сообщения по собственному onion-адресу.
* **Релей — только удобство.** Он хранит зашифрованные сегменты, пока адресат не заберёт, и ищет
  людей по нику. Прочитать их он не может и ничего не проверяет: проверяет получатель.

## Установка

Готовые APK: **[последняя сборка](../../releases/tag/latest)**. Для обычной установки выберите
`eidolang-*.apk` без суффикса `-migration`. Сборка `-migration.apk` предназначена для параллельного
подключения к первой публичной версии с другой подписью; порядок ниже.

Нужен Android 8.0 или новее. Разрешите установку из неизвестного источника для того приложения,
из которого открываете файл. Релизные APK подписываются одним постоянным ключом, поэтому
следующую версию можно установить поверх предыдущей с сохранением данных.

### «Конфликтует с другим пакетом»

Если EidoLang уже установлен, причиной может быть другая подпись старой сборки. Раньше APK
собирались с отладочным ключом конкретного компьютера или одноразового GitHub runner; такие
версии не могут обновлять друг друга. Новый процесс публикации сохраняет сертификат APK
`v0.1-R22.1` (SHA-256: `17fcaa77ef0390630829ecb65afd0dedb3d60b27dda2182c1349adc336eed0f3`).

**Не удаляйте приложение без проверенной резервной копии:** удаление может уничтожить локальную
историю и ключи. Если подпись установленной версии отличается, для обновления без удаления
нужен её исходный ключ подписи; иначе потребуется резервная копия истории и отдельный перенос.
Если ошибка возникает при первой установке, проверьте также рабочий профиль, других пользователей
телефона и клоны приложений: EidoLang может быть установлен там.

### Сохранение профиля первой публичной версии

Первая публикация `eidolang-2efeb51.apk` была подписана ключом одноразового GitHub runner,
который не сохранялся. Совместимое обновление поверх неё недоступно. Если важны профиль и
переписка, **оставьте старое приложение установленным** и используйте `-migration.apk`.
Оно называется **«EidoLang — дополнительная установка»**, устанавливается рядом и получает
от прежнего профиля разрешение работать как ещё одно устройство. Идентификатор пользователя,
имя и фото из визитки сохраняются; новый основной профиль не создаётся. У дополнительной установки
отдельный сетевой адрес, поэтому обе версии могут работать рядом. Он сохраняется при обновлениях,
но меняется при переустановке дополнительного приложения.

Это не перенос основного закрытого ключа: он остаётся в старом приложении, которое нужно
сохранить и после подключения. Его текущая полная переписка остаётся на месте. Старый secure
export содержит эйдограммы, контакты и метаданные диалогов, **но не текстовые подписи к
сообщениям, фото контактов, сетевые адреса и несохранённые в переписке эйдограммы**.
Поэтому восстановление этого архива не считается полной копией старой установки.

Порядок подключения на одном телефоне:

1. В старом EidoLang: **«Ещё» → «Как вас добавить» → «Сохранить визитку файлом»**.
2. Установите APK с суффиксом `-migration`. В дополнительной установке выберите сохранённую
   визитку и нажмите **«Сохранить запрос на подключение»**.
3. В старом приложении: **«Ещё» → «Устройства, архивы, диагностика» → «Устройства» →
   «Авторизовать enrollment request»**. Выберите запрос дополнительной установки, затем
   **«Экспортировать device bundle»** и **«Экспортировать новый roster»**.
4. В дополнительной установке выберите разрешение (`device bundle`) и список устройств
   (`roster`). Незавершённое подключение сохраняется при закрытии приложения. Если старое
   приложение сбросило экран до экспорта файлов, повторно авторизуйте тот же запрос.
5. **После авторизации** откройте в старом приложении **«Архив» → «Secure export»** и сохраните
   архив. Затем **«Recovery backup»** — сохраните файл и отдельно его recovery code.
6. В дополнительной установке: **«Ещё» → «Устройства, архивы, диагностика» → «Архив»**.
   Выберите `Vault package`, `Recovery backup`, введите recovery code и нажмите
   **«Проверить и восстановить»**. Для свежей установки появится предупреждение о невозможности
   доказать свежесть архива; продолжайте только с только что созданным вами архивом.
7. Проверьте профиль и доступную историю в дополнительной установке. Чтобы собеседники
   обращались к новому устройству, передайте им его новую визитку. Старую установку сохраняйте
   для основного ключа и полной исходной переписки.

## Первый запуск

1. Приложение попросит имя и фото. **Имя увидят те, кому вы дадите код или ссылку** — оно
   записано в вашей визитке; фото они забирают с вашего телефона. Больше никуда ни то, ни другое
   не отправляется.
2. К имени добавится метка из вашего ключа: `Катман#7f3a`. Тёзки возможны, перепутать вас нельзя —
   метка берётся из ключа, и присвоить чужую без его закрытой части невозможно.
3. Приложение начнёт поднимать Tor. На это уходит **до двух-трёх минут**, в сетях с блокировками —
   через мосты. Пока адрес не поднялся, знакомство по коду не сработает: визитка забирается прямо
   с вашего устройства.

## Как добавить собеседника

**«Ещё» → «Как вас добавить»** — там QR-код, ссылка и кнопка «Поделиться».

* **Рядом:** покажите QR. Его читает обычная камера — приложение откроется само.
* **На расстоянии:** «Поделиться» отправит ссылку и картинку в любой мессенджер или почту, или
  скопируйте ссылку кнопкой.
* **По нику:** «Контакты» → «Найти людей». Работает, только если человек **сам** включил
  «Меня можно найти по нику»: имя в профиле никого никуда не записывает.
* **Файлом:** визитку можно сохранить и передать как файл — единственный способ, вообще не
  требующий сети.

Знакомство взаимное: чтобы получать от человека, добавьте его и вы.

## Переписка

**«Эйдограммы» → «Создать».** Редактор открывается в режиме перемещения — нажатия по холсту ничего
не ставят. Выберите семейство в палитре, и нажатие начнёт ставить фигуры; «Перемещать» выключает
обратно.

* **Наложение** — долгое нажатие ставит фигуру поверх другой (треугольник внутри круга).
* **Квадраты** — в палитре доступны те же 10 цветов и размеры S/M/L, что у кругов и треугольников.
* **Линии** — выберите «Линии» и проведите пальцем между двумя точками. Цвет и толщина берутся из
  палитры; растягивание меняет длину, а не толщину.
* **Размер и поворот** — двумя пальцами.
* **Слова обязательны.** Сохранить эйдограмму без описания нельзя: смысл в этом языке не задан
  заранее, и подпись — единственное, что связывает вашу композицию с тем, что вы имели в виду.

Отправка — кнопка «Отправить» на эйдограмме или «Написать» прямо в чате.

### Галочки

* **✓ ждёт получателя** — опубликовано, ещё не забрали.
* **✓✓ доставлено** — все файлы сообщения ушли с вашего устройства или из камеры хранения релея.

Утверждение узкое и честное: две галочки значат, что **байты ушли**, а не что их прочитали.
Забирающий не аутентифицирован — адрес есть на визитке, — так что теоретически галочку может
поднять и посторонний с вашей визиткой. Он получит шифротекст.

### Получение

**«Обновить»** в шапке. Приложение опрашивает три маршрута **одновременно** — onion собеседника,
камеру хранения релея и DHT — и берёт то, что ответит первым. Обычно это несколько секунд.

Если сообщение не приходит, приложение называет причину, а не отмалчивается: «нет ключа публикации»,
«ваша сеть Tor ещё поднимается», «объявления нет — устройство собеседника, похоже, не в сети».

### Выгрузка переписки

В шапке чата — **«Выгрузить в Word»**: `.docx` с картинками эйдограмм и подписями, сразу уходит в
меню «Поделиться». Это читаемая копия: ни ключей, ни подписей, ни идентификаторов сообщений,
обратно не загружается.

## Свой релей

Релей не обязателен, но без него оба устройства должны быть в сети одновременно.

```bash
git clone https://github.com/catman77/EidosLang.git
cd EidosLang
sudo ./relay/install.sh
```

Скрипт кладёт файлы в `/opt/eidolang-relay`, собирает образ, поднимает контейнер с
`--restart unless-stopped` и **проверяет, что релей отвечает**, а не только что контейнер
запустился. Нужны Docker и открытые порты **6881** (TCP+UDP, рой) и **6882** (TCP, HTTPS).

Данные — в томе `eidolang-relay-state`; пересоздание контейнера их не трогает.

### О сертификате — прочитайте, если меняете адрес

Приложение доверяет **сертификату**, а не адресу. Это позволяет переносить релей куда угодно, но
означает: релей с **новым** сертификатом приложение отвергнет. Принимать любой предъявленный
сертификат было бы хуже, чем разрешить открытый трафик.

* Переносите релей — скопируйте старый сертификат: `sudo ./relay/install.sh --cert /старый/tls`.
* Ставите свой с нуля — сертификат придётся вложить в приложение и пересобрать его:

```bash
cp /opt/eidolang-relay/tls/cert.pem android/app/src/main/res/raw/eidolang_relay.pem
cp /opt/eidolang-relay/tls/cert.pem android/feature-home/src/main/res/raw/eidolang_relay.pem
```

Адрес релея меняется в приложении: **«Ещё» → «Адрес релея»**, с проверкой связи по кнопке.

### Что релей видит и чего не видит

Он хранит подписанные «головы» и зашифрованные сегменты и **не может их прочитать**: полезная
нагрузка зашифрована на получателя, в обмене ключами релей не участвует. Проверяет он только
подпись головы; содержимое сегмента проверяет получатель.

Чего он всё же видит: кто что публикует, какого размера и когда. Это цена за то, чтобы не держать
оба телефона онлайн одновременно. Забранный сегмент отправитель удаляет подписанным запросом;
непонадобившееся вычищается по сроку.

## Сборка из исходников

```bash
cd android
gradle :app:assembleDebug          # нужен Gradle 9.5.0 и Android SDK с platform 37
```

Обёртки Gradle в репозитории нет намеренно: AGP 9.3.0 требует Gradle 9.5.0, а создать обёртку более
старым Gradle не удаётся — сборка не доходит до этой стадии. Возьмите дистрибутив 9.5.0 напрямую
или откройте проект в Android Studio.

Каждый пуш в `main` собирается на GitHub Actions, и APK выкладывается в релиз `latest`.
Публикуются `:app:assembleRelease` и `:app:assembleMigration`; pull request проверяется
отладочной сборкой без доступа к ключу. Параллельная сборка использует постоянный
`applicationId = org.eidolang.app.migration`, поэтому её дальнейшие версии обновляют её же.
Оба процесса публикации используют одни и те же GitHub Actions secrets:

* `EIDOLANG_KEYSTORE_BASE64` — постоянное хранилище ключа в base64;
* `EIDOLANG_STORE_PASSWORD` — пароль хранилища;
* `EIDOLANG_KEY_ALIAS` — имя ключа;
* `EIDOLANG_KEY_PASSWORD` — пароль ключа.

Для локальной релизной сборки задайте `EIDOLANG_KEYSTORE_FILE` (абсолютный путь к хранилищу) и
три переменные пароля/имени ключа из списка выше, затем выполните `gradle :app:assembleRelease`.
Без этих настроек релизная сборка завершается ошибкой. Перед публикацией выполняется
`bash android/tools/verify-apk-signature.sh android/app/build/outputs/apk/release/app-release.apk`:
он проверяет подпись APK и соответствие сертификату из `android/signing-certificate.sha256`.
Закрытый ключ не хранится в репозитории; при смене runner его нужно восстановить из секрета,
а не создавать заново.

### Раскладка

| Каталог | Что там |
|---|---|
| `android/` | приложение: `core-*` — протокол, `feature-*` — экраны, `app` — оболочка |
| `relay/` | релей (один файл на Python), Dockerfile и установщик |
| `docs/` | нормативная спецификация и замороженные архивы релизов R1–R22 |

Ядро протокола в `core-*` — чистый Kotlin и JCA: только файлы `Android*.kt` касаются Android SDK.
Благодаря этому весь стек компилируется отдельным `kotlinc` и проверяется на JVM без Android —
эти наборы в `android/tools/` и есть главный контур регрессии.
